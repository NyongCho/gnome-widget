# GNOME Liquid Glass Widgets — PRD

버전: 1.0 · 기준 확정일: 2026-11-03 · 상태: 제품 요구사항 기준 승인, 구현 전

프로젝트: `/home/nyong/projet/gnome-widget`

## 1. 제품 정의

Ubuntu GNOME 바탕화면에서 시간·일정·날씨·PC 상태를 한눈에 확인하는 개인용 위젯 모음이다. macOS Liquid Glass에서 영감을 받은 투명감, 배경 굴절, 절제된 반사광을 적용한다. 예쁜 바탕화면을 만드는 것과 실제로 읽고 사용할 수 있는 정보를 제공하는 것을 함께 목표로 한다.

사용자는 Conky 형태의 위젯을 원했으나 기존 테마의 외형에 만족하지 않았고, Mac과 유사한 시각적 완성도와 Google Calendar 연동을 요청했다. 기술 검토와 구현 계획은 마련됐지만 제품의 범위·기본 동작·인수 기준을 한 문서로 확정하지는 않았다. 이 PRD가 그 기준이 된다.

이 문서는 무엇을 왜 만드는지와 완료 조건을 정의한다. API·파일 구조·라이브러리 선택은 [기술 설계](liquid-glass-design.md), 작업 순서는 [구현 계획](liquid-glass-plan.md), 호환성 근거는 [저장소 검토](liquid-glass-repository-review.md)에 둔다. 기술 문서는 이 PRD를 기준으로 관리한다. 승인 상태는 구현이나 실측 완료를 뜻하지 않는다.

## 2. 대상 사용자와 해결할 문제

첫 사용자는 현재 Ubuntu 데스크톱을 사용하는 프로젝트 소유자다. 첫 버전은 이 PC에서 일상적으로 사용할 수 있는 수준을 목표로 한다. 다른 사용자에게 배포하는 범용 위젯 플랫폼은 별도 범위다.

| 상황 | 필요한 경험 |
|---|---|
| 바탕화면을 잠깐 확인한다 | 오늘 날짜, 다음 일정과 날씨를 여러 앱을 열지 않고 파악한다. |
| 일정의 자세한 내용이나 편집이 필요하다 | 달력·일정 카드를 눌러 Google Calendar로 이동한다. |
| 다운로드나 작업 중 PC 상태가 궁금하다 | 네트워크 속도·CPU·RAM·온도를 간단하게 확인한다. |
| 바탕화면을 꾸민다 | 정보가 정돈된 유리 카드가 배경과 자연스럽게 어울린다. |
| 평소 앱을 사용한다 | 위젯이 창·아이콘·키보드 입력을 방해하지 않는다. |

## 3. 확인된 방향과 채택한 초기 기본값

**대화에서 확인된 방향:** Ubuntu GNOME 바탕화면 위젯, Mac/Liquid Glass 느낌, 날짜·날씨·네트워크 등 여러 정보 카드, Google Calendar 연동과 클릭 시 브라우저 열기, Rust + TypeScript + 셰이더 조합.

**기존 설계의 제안에서 채택한 초기 기본값:** 읽기 전용 iCal 연결, 현재 달 중심의 달력, 다음 일정 3개, 날씨 지역 1곳, 하나의 모니터에 위젯 묶음 배치, 재생 중일 때만 음악 카드 표시. PRD 승인에 따라 첫 버전의 기준으로 사용한다. 기술 검증에서 변경 필요성이 드러나면 영향을 기록하고 범위를 조정한다.

## 4. 목표와 첫 버전의 범위

첫 완성 버전에는 다음 기능을 모두 포함한다. 개발 중간의 단일 카드 시제품과 완성 버전을 구분하며, 카드를 사용자가 숨길 수 있다는 것은 해당 기능의 구현을 생략한다는 뜻이 아니다.

| ID | 기능 | 첫 버전 범위 |
|---|---|---|
| F-01 | Liquid Glass 외형 | 둥근 카드, 배경화면 굴절, 블러, 반사 테두리, 선명한 전경 텍스트 |
| F-02 | 날짜·시계 | 날짜·요일·시각, 시스템 시간대와 시간 표시 형식 반영 |
| F-03 | 월간 달력 | 현재 달, 오늘 강조, 일정이 있는 날짜 표시 |
| F-04 | Google 일정 | 캘린더 1개 읽기 전용 연결, 진행 중·다가오는 일정 최대 3개, 브라우저 열기 |
| F-05 | 날씨 | 사용자가 선택한 지역 1곳의 현재 날씨·기온과 향후 6시간 예보 |
| F-06 | 시스템 상태 | 전체 CPU 사용률, RAM 사용량, 가능한 경우 온도 |
| F-07 | 네트워크 | 선택 인터페이스의 다운로드·업로드 속도와 최근 60초 변화 |
| F-08 | 음악 | 지원 플레이어의 재생 중 곡·아티스트, 가능한 경우 앨범 이미지 |
| F-09 | 배치·설정 | 모니터, 위치, 전체 크기, 카드 표시 여부, 불투명도·굴절 강도·저전력 설정 |
| F-10 | 상태·복구 | 연결 전·로딩·빈 결과·오프라인·오류 구분, 마지막 성공 데이터와 자동 복구 |

첫 버전에서 제외하는 기능은 일정 생성·수정·삭제, 여러 캘린더 통합, 지난달·다음 달 탐색, 일정 알림, 음악 재생 제어, 여러 모니터에 위젯 복제, 자유로운 카드별 드래그 편집, 사용자 제작 위젯 플러그인, 다른 데스크톱 환경 지원이다. 범위를 바꿀 때는 PRD를 먼저 조정한다.

## 5. 시각적 방향과 배치

- 배경을 일부 볼 수 있는 둥근 유리 카드, 약한 광택, 일정한 간격과 글자 위계를 사용한다. 강한 네온 색이나 과도한 장식은 기본 스타일로 사용하지 않는다.
- 굴절은 카드 뒤 배경화면에 적용한다. 숫자·일정 제목·아이콘은 굴절시키지 않는다. 앱 창이나 화면 전체를 굴절시키는 효과는 범위에 넣지 않는다.
- 밝은 배경, 어두운 배경, 무늬가 복잡한 배경에서도 주요 텍스트를 읽을 수 있어야 한다. 효과 강도를 높여도 텍스트의 선명함을 유지한다.
- 기본 배치는 선택한 모니터의 오른쪽 위다. 시계, 달력·날씨, 일정·네트워크, 선택한 시스템·음악 카드 순으로 정돈하고 공간이 부족하면 1열로 전환한다.
- 기본 표시 카드는 시계·달력·일정·날씨·네트워크다. 시스템·음악은 설정에서 켤 수 있다. 숨긴 카드나 숨겨진 음악 카드 때문에 큰 빈 공간이 남지 않는다.
- 정확한 색상·폰트 크기·여백은 실제 GNOME 카드 시제품에서 조정한다. 기존 [HTML 미리보기](liquid-glass-preview.html)는 배치 참고 자료이며 최종 디자인이나 런타임 검증 결과가 아니다.

## 6. 주요 사용 흐름

**처음 사용:** 설치 후 확장을 켠다. 시간과 로컬 상태는 바로 표시되고, 일정·날씨에는 짧은 설정 안내가 나온다. 설정 창에서 캘린더 연결, 날씨 지역, 표시할 카드와 위치를 지정한다. 계정을 연결하지 않아도 나머지 카드를 사용할 수 있다. 예시 데이터를 실제 일정이나 날씨처럼 보여주지 않는다.

**일상 확인:** 바탕화면으로 돌아왔을 때 최신 정보가 보인다. 앱 창을 열면 위젯은 그 뒤에 머문다. 카드 밖에서는 아이콘 클릭·드래그·우클릭이 기존처럼 동작한다.

**일정 열기:** 달력이나 일정 카드를 클릭하면 기본 브라우저로 Google Calendar를 연다. 날짜별 링크가 검증되지 않은 경우 캘린더 홈을 연다. 브라우저 로그인은 브라우저가 처리한다. 특정 이벤트 상세 화면까지 바로 여는 것은 첫 버전의 필수 조건이 아니다.

**연결 장애:** 날씨나 일정 갱신에 실패해도 다른 카드는 정상 동작한다. 마지막 성공 데이터가 있으면 오래된 정보임을 표시하고 유지한다. 연결이 복구되면 확장을 다시 켜지 않아도 재시도한다.

**잠금·재접속:** 화면 잠금 중에는 위젯과 일정이 보이지 않는다. 잠금 해제·절전 복귀 뒤에는 저장된 배치로 돌아오고 필요한 데이터를 갱신한다.

## 7. 기능별 동작과 인수 기준

| ID | 요구 동작 | 확인 방법·완료 기준 |
|---|---|---|
| F-01 | 굴절을 실제로 렌더링하고 글자는 별도 표시한다. | 대비가 있는 배경에서 굴절 0과 양수를 비교해 배경 윤곽의 왜곡을 확인한다. 텍스트는 변형되지 않는다. 실제 PC에서 시각 검토를 받는다. |
| F-02 | 시각은 최소 분 단위로 맞추고 날짜·요일을 함께 표시한다. 초 단위 표시는 필수가 아니다. | 자정, 시스템 시간대·12/24시간 형식 변경, 절전 복귀 뒤 표시가 맞다. |
| F-03 | 시스템의 주 시작 요일을 반영하고 오늘·일정 표시점을 구분한다. | 월 경계, 여러 날 일정, 종일 일정이 정확한 날짜에 표시된다. 달력 클릭으로 Google Calendar가 열린다. |
| F-04 | 종료되지 않은 일정 중 진행 중인 것을 먼저, 이후 일정을 시작 시각순으로 최대 3개 보여준다. 종일 일정은 종일로 표시한다. | 반복·변경·취소·시간대·여름시간 테스트에서 중복이나 잘못된 날짜가 없다. 30일 이내 일정이 없으면 빈 상태를 표시한다. 긴 제목은 레이아웃을 깨지 않고 축약한다. |
| F-05 | 현재 날씨·섭씨 기온과 향후 6시간 예보를 표시한다. 지역명과 데이터 출처를 확인할 수 있다. | 설정 지역과 공급자 응답이 일치하며 누락된 값을 0으로 꾸미지 않는다. 다른 지역을 선택하면 이전 지역의 데이터를 현재 값처럼 표시하지 않는다. |
| F-06 | CPU·RAM과 식별 가능한 센서 온도를 표시한다. | 비교 도구와 사용량 정의를 맞춰 확인한다. 온도 센서가 없으면 사용 불가로 표시하며 0°C를 만들지 않는다. 첫 CPU 표본을 실제 부하로 오인하지 않는다. |
| F-07 | 기본 경로 인터페이스를 초기 선택하고 수동 선택을 지원한다. | 업·다운로드가 구분되고, Tailscale과 물리 NIC를 합산하지 않는다. 인터페이스 전환·카운터 초기화 시 속도가 폭증하지 않는다. |
| F-08 | 지원 플레이어가 재생 중일 때만 표시한다. | 재생·일시정지·종료에 따라 표시/숨김이 맞다. 여러 플레이어가 재생 중이면 일관된 규칙으로 하나를 선택한다. 이미지가 없어도 곡 정보를 읽을 수 있다. |
| F-09 | 설정을 저장하고 배율·작업 영역에 맞춰 배치한다. | 재로그인 뒤 설정이 유지된다. 선택한 모니터가 사라지면 남은 모니터에 접근 가능한 위치로 옮긴다. 작은 화면에서 카드와 필수 설정에 접근할 수 있다. |
| F-10 | 각 데이터 카드의 상태를 독립적으로 관리한다. | 일정 오류가 날씨·시계까지 멈추게 하지 않는다. 연결 복구·서비스 재시작 뒤 자동으로 정상 상태로 돌아온다. |

일정 조회 범위는 현재 월 달력 그리드 전체와 현재부터 30일을 합친 범위다. 진행 중 일정은 종료 시각이 현재보다 늦은 경우에 포함하며, 종일 일정 종료일은 그 날짜를 포함하지 않는 규칙으로 해석한다. 그 밖의 동률 정렬, 지원 센서 선택, 숫자 포맷은 일관된 규칙을 정해 구현 문서에 기록한다.

## 8. 데이터 갱신과 상태 표시

아래 주기는 기존 기술 계획에서 가져온 초기값이다. 공급자의 갱신 지연까지 보장하는 실시간 동기화 약속은 아니다.

| 데이터 | 정상 동작 시 갱신 제안 |
|---|---|
| 시각 | 분 경계와 시스템 시간·시간대 변경 시 |
| CPU·RAM·네트워크 | 약 2초 |
| 온도 | 약 5초 |
| Google Calendar | 약 5분 간격으로 조회 |
| 날씨 | 약 15분 간격으로 조회 |
| 음악 | 플레이어 상태 변경 시 |

| 상태 | 사용자에게 보여줄 내용 |
|---|---|
| 미설정 | 연결·지역 설정 안내. 전체 사용을 막는 팝업은 띄우지 않는다. |
| 최초 로딩 | 짧은 로딩 표시. 임의의 수치를 실제 값으로 표시하지 않는다. |
| 정상·빈 결과 | 현재 데이터 또는 “예정된 일정 없음”처럼 의미가 명확한 빈 상태 |
| 갱신 실패·기존 데이터 있음 | 마지막 데이터를 유지하고 오래된 상태 및 마지막 성공 시각 표시 |
| 갱신 실패·기존 데이터 없음 | 사용 불가 이유와 사용자가 취할 수 있는 조치 |
| 연결 해제·지역 변경 | 이전 연결·지역의 내용을 새 대상 데이터로 재사용하지 않는다. |

갱신이 예정된 시점에 성공 응답을 받지 못했거나 서비스 연결이 끊기면 오래된 상태로 전환한다. 대기·재시도 중에는 마지막 성공 시각을 갱신하지 않는다. 오류 안내에는 비공개 주소, 인증값, 원문 스택 추적을 표시하지 않는다.

|---|---|---|
| Q-01 | 일반 데스크톱 사용을 방해하지 않는다. | DING 아이콘, 일반 창, Ubuntu Dock, overview·workspace 전환, Blur my Shell 공존을 실제 환경에서 확인한다. 위젯이 자동으로 키보드 포커스를 빼앗지 않는다. |
| Q-02 | 정적인 위젯 때문에 지속적으로 높은 부하가 생기지 않는다. | 동일 조건의 OFF/ON 비교 3회. 초기 목표는 서비스 CPU 평균 한 논리 코어의 1% 이하, RSS 100MiB 이하, 전경 창 이동 시 프레임 시간 p95 증가 2ms 이하. Shell CPU/RSS와 GPU 메모리 비용도 기록한다. |
| Q-03 | 켜고 끄기와 시스템 상태 변화에 견딘다. | 30분 사용, enable/disable 20회, 화면 잠금, 절전 복귀, 모니터 분리, 서비스 재시작에서 셸 오류·중복 카드·자원 누적이 없다. |
| Q-04 | 비공개 일정 연결 정보를 보호한다. | 연결 주소는 로컬 비밀 저장소에 보관하고 저장 후 다시 노출하지 않는다. 로그·일반 설정·상태 전달·저장소에 포함하지 않는다. 일정 캐시는 사용자 전용 권한으로 저장하며 연결 해제 시 제거한다. |
| Q-05 | 잠금 화면에서 개인 일정을 노출하지 않는다. | 잠금 화면·로그인 화면에 위젯을 표시하지 않는다. |
| Q-06 | 정보가 읽히고 설정을 조작할 수 있다. | 밝음·어두움·복잡한 배경과 100%·분수 배율에서 글자·단위가 잘리지 않는다. 상태는 색상만으로 구분하지 않는다. 설정 창은 키보드로 조작할 수 있다. |
| Q-07 | 사용자가 설치를 되돌릴 수 있다. | 사용자 영역 설치·제거 경로를 제공한다. 제거 후 다른 확장과 데스크톱 설정이 유지되며, 설정·캐시·비밀정보 삭제 옵션을 별도로 제공한다. |

성능 숫자는 아직 측정되지 않은 제안 목표다. 하드웨어·측정 도구·조건과 미달 항목을 함께 기록한다. 목표를 달성하지 못한 경우 값을 몰래 완화하지 않고, 효과 품질 또는 범위의 조정안을 제시한다. headless 테스트 통과를 실제 GPU 성능 검증으로 대체하지 않는다.

## 10. 기술적 제약과 구현자에게 맡길 결정

사용자가 선택한 Rust + TypeScript + 셰이더 조합을 유지한다. 첫 지원 환경은 조사 당시의 Ubuntu 26.04.1, GNOME Shell 50.1, Wayland다. root 상주 서비스, 외부 수신 포트, Mutter 수정은 요구하지 않는다.

현재 설계의 iCal 연결은 제안된 수단이다. Google Calendar 내용을 정확하게 읽고 브라우저로 연결하는 것이 제품 요구다. iCal로 요구 정확성을 충족하지 못하면 대안을 비교하고, 계정 연결 경험이나 범위가 바뀌는 부분을 먼저 설명한다.

라이브러리 버전, 데이터 계약의 세부 구조, 효과 버퍼·캐시, 테스트 도구, 파일 분할은 구현자가 결정한다. 지원 플랫폼·필수 카드·개인정보 처리·사용자 연결 방식·실제 굴절 여부를 바꾸는 선택은 제품 범위 변경으로 기록한다.

굴절이 지원되지 않을 때는 명시적인 저전력/반투명 모드를 제공할 수 있다. 다만 현재 대상 PC에서 굴절을 구현하지 못한 상태를 F-01 충족으로 처리하지 않는다. 첫 버전의 핵심 시각적 요구를 바꾸는 결정은 사용자와 별도로 논의한다.
